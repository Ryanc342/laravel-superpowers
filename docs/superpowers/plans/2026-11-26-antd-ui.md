# Template UI on Ant Design Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the template's shadcn UI, its 84 shared components and its UI rules with Ant Design 6 and Pro components, plus a thin layer of glue to Laravel and Inertia. The release adds bilingual text, Fortify feature switches and a working example for each common back-office page type, and ships as `sp-v2.0.0`.

**Architecture:** Every page is composed directly from antd and Pro components; there is no wrapper layer of our own.

- **Styles:** generated at build time into an `antd` CSS layer (zeroRuntime). Dark mode switches CSS variables under `html.dark`.
- **Glue:** the template owns only the glue under `resources/js/ui/`: theme, lists, forms, feedback, dialogs and appearance. It also owns `lib/i18n.ts`, and on the server a `ListRequest` base class, a `Locale` enum and a `SetLocale` middleware.
- **Order:** the old components stay until the last code task, so every task keeps `composer check` (and, for UI tasks, `composer check:browser`) green.

**Tech Stack:**

- Laravel 13, Fortify, Inertia v3 (React 19, SSR), Wayfinder;
- antd 6, `@ant-design/pro-components` 3 beta, `@ant-design/cssinjs`, dayjs;
- Tailwind v4 (marketing pages only);
- Vite+ (`vp`), Vitest, Pest 5 with the browser plugin (Playwright).

**Spec:** `docs/superpowers/specs/2026-11-26-antd-ui-design.md`. Read it before any task. It is the authority when this plan is silent or unclear.

## Global Constraints

**Dependencies**

    - `@ant-design/pro-components` 3.x beta, pinned exactly: take the latest `beta` dist-tag that works and write it with no `^` or `~`;

- Keep `tailwindcss` and `@tailwindcss/vite`, for the welcome page and marketing pages only. App pages, which are inside the app or auth layout, use no Tailwind classes and no `style` props for colours or spacing.

**Styling**

- The CSS layer order is exactly `@layer theme, base, antd, components, utilities;`.
- The brand colour is `#155dfc`. The font is Instrument Sans, then system Chinese fonts: `'Instrument Sans', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', ui-sans-serif, system-ui, sans-serif`.
- Control sizes are antd's defaults (32px). Do not set `size="large"` globally.
- The antd CSS-variable key is `app`.

**Language and copy**

- `config('app.locale')` defaults to `zh_CN` (`APP_LOCALE`). `config('app.fallback_locale')` is `en`. The browser's language is never consulted.
- The test suite runs in English: `phpunit.xml` sets `APP_LOCALE=en`. Tests that check Chinese switch the locale themselves.
- Every user-visible string goes through `t()`/`tChoice()` (React) or `__()` (PHP). It is keyed by its English text and translated in `lang/template/zh_CN.json`, which is template-owned. The project's `lang/zh_CN.json` is not shipped.
- Copy rules:
    - Chinese uses "你";
    - put a space between Chinese and Latin letters or numbers;
    - dates are written `2026-11-26`;
    - no full stop at the end of short English UI text (labels, buttons, titles, hints);
    - "登录", never "登陆".

**Behaviour and scope**

- The rows-per-page choices are `[10, 20, 50, 100]`, with a default of `20`. Both live in `config/lists.php`.
- The error statuses rendered by the `error` page are 403, 404, 419, 429, 500 and 503, outside debug mode.
- SSR stays on. Nothing may touch `window`/`document` during render; use effects.
- Examples exist only in the `local` and `testing` environments.

## Review Focus

1. **A hand-edited or old list URL** (`per_page=7`, a sort column that is not allowed, `page=999`, a malformed filter) still loads the list. It uses the defaults, and a page past the end is clamped to the last page, with no 422 and no redirect loop. Test in Task 7.
2. **A sentence missing from both JSON files, or one with placeholders and plurals in Chinese,** never crashes. A missing sentence shows its English text. Test in Task 3.
3. **A guest who chose a language, then signs in as a user who saved a different one,** gets the user's saved choice. Switching while signed in updates both the column and the cookie. Test in Task 2.
4. **Server errors for nested fields** (`items.0.name`) land under the right field. An error for a field the form doesn't show is not lost: it appears in a form-level `Alert`. Test in Task 6.
5. **A form submitted after the session expired (419), or a login throttled (429),** shows the translated error page or message, not a broken form. Test in Task 11.
